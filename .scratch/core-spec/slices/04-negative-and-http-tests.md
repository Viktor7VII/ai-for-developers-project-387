## Проверка с намеренно отключённой блокировкой (ADR-0002)

Выполнена 2026-11-23 локально (Windows, Java 21).

1. Блокировка временно убрана из `BookingService`: вызовы `bookingLock.lock()` и `bookingLock.unlock()` заменены комментариями (файл восстановлен сразу после прогона).
2. Команда в `backend/`:
   ```
   ./mvnw test -Dtest=BookingRulesViolationTests#concurrentOverlappingRequestsWithDifferentStartsNeverOverlap
   ```
3. Результат без блокировки — **тест упал**:
   ```
   AssertionFailedError: overlapping bookings: 2026-11-16T09:00:00Z and 2026-11-16T09:15:00Z
   Tests run: 1, Failures: 1, Errors: 0, Skipped: 0
   ```
   Причина: одновременные записи `strategy` 09:00–10:00 и `quarter` 09:15–09:30 начинаются в разное время, поэтому уникальность начала в базе их не остановила, и обе сохранились — двойная запись.
4. Блокировка восстановлена; повтор `./mvnw test -Dtest=BookingRulesViolationTests` — **4 из 4 тестов прошли**.

Замечание: первая версия теста (все потоки на одно время) без блокировки падала только на уникальности начала (`DataIntegrityViolationException: UK_BOOKINGS_START_AT`) и не доказывала защиту от пересечений с разным началом; тест переделан до коммита. Аналогичная ручная проверка теста гонки на одно время выполнялась в первой версии бэкенда.
