# Спецификация основной функциональности «Календаря звонков»

> Перенесено из первого проекта [ai-for-developers-project-386](https://github.com/Viktor7VII/ai-for-developers-project-386). Оригинал карты — https://github.com/Viktor7VII/ai-for-developers-project-386/issues/3, спецификация — https://github.com/Viktor7VII/ai-for-developers-project-386/issues/19, тикеты решений — https://github.com/Viktor7VII/ai-for-developers-project-386/issues/4 – https://github.com/Viktor7VII/ai-for-developers-project-386/issues/18. Хеши коммитов и номера PR в `.scratch/` относятся к истории первого проекта.

## Destination

Согласованная спецификация приложения: поведение владельца и гостя, модель данных, API-контракт, правила записи и слотов, границы тестирования. Готова к декомпозиции на вертикальные тикеты и реализации без новых функциональных уточнений.

## Notes

- Термины — строго по `GLOSSARY.md` («гость», «запись», «тип встречи», «слот», «ссылка для записи»); решения — с учётом `docs/adr/`.
- Каждый grilling-тикет решается со скиллами `grilling` и `domain-modeling`: новые термины сразу в `GLOSSARY.md`, решения уровня ADR — в `docs/adr/`.
- Один тикет за сессию (кроме research). Код, контракт и генерацию на этом этапе не трогаем.
- Уже реализованное — текущее состояние, а не утверждённое решение. В каждом тикете есть раздел «Текущее состояние»; расхождения с принятым решением фиксируются в ответе тикета.
- Текущее состояние (master `33f6161`) кратко: один владелец без входа (ADR-0001); типы встреч — создание, просмотр, редактирование, без удаления; расписание — недельные интервалы, несколько в день, часовой пояс (по умолчанию UTC); слоты — шаг равен длительности, от начала интервала, окна записи нет (запрос до 62 дней); конфликт — любая запись занимает время для всех типов, примыкание разрешено, гонки — блокировка в приложении + уникальность начала в БД, ответ 409; цепочка TypeSpec → OpenAPI → TS SDK, серверный код написан вручную; тесты — JUnit/MockMvc и Vitest, браузерных нет; CI — `mise run check`, release-please нет.

## Decisions so far

<!-- одна строка на закрытый тикет: [название](issues/NN-slug.md): суть ответа -->

- [Роли и доступ: кто владелец и что доступно гостю](issues/01-roles-and-access.md): владелец единственный и неявный, без профиля; гостю доступны только список типов встреч, страница типа встречи, свободные слоты и создание записи; кабинет открыт (ADR-0001).
- [Типы встреч: операции и данные](issues/02-event-types.md): создание, просмотр, редактирование всех полей в любое время, удаление только без записей (архива нет); поля и ограничения без изменений; записи сохраняют своё время, старая ссылка не перенаправляется.
- [Расписание: рабочие дни, часы и часовой пояс владельца](issues/03-schedule.md): любое число интервалов в любой день (перерывы — несколько интервалов), правила интервалов без изменений; часовой пояс в расписании, только IANA, по умолчанию UTC; изменение расписания и пояса не трогает записи, местные часы сохраняются; DST — текущее поведение; по умолчанию пн–пт 09:00–17:00 UTC.
- [Окно записи: 14 календарных дней](issues/04-booking-window.md): фиксированные 14 календарных дней от сегодняшнего включительно в поясе владельца, до 00:00 пятнадцатого дня; слот — по началу, без минимального отступа; сервер повторно проверяет окно при записи; без автообновления страницы; существующие записи вне окна сохраняются; запрос вне окна — пустой список.
- [Модель слотов: шаг стартов и формирование](issues/05-slot-model.md): шаг равен длительности, сетка от начала каждого интервала, слот целиком внутри интервала (остаток отбрасывается, примыкающие интервалы не склеиваются); совпадает с текущей реализацией.
- [Модель записи: сущности, связи, обязательные поля](issues/06-booking-model.md): запись ссылается на тип встречи (показывается текущее название), хранит имя и email гостя, начало, конец, время создания; единственный статус «подтверждена», отмены нет; совпадает с текущей реализацией.
- [Конфликты: пересечения, примыкание, одновременные запросы](issues/07-conflicts.md): занятость общая для всех типов, интервалы полуоткрытые, примыкание разрешено, буферов нет; двойная запись исключена блокировкой в приложении с повторной проверкой в одной транзакции + уникальность начала (ADR-0002); проигравший получает «слот недоступен».
- [API-контракт: эндпоинты, запросы и успешные ответы](issues/08-api-endpoints.md): кабинет `/api/…` (типы встреч с новым DELETE, расписание, записи), публичный `/api/public/…` (тип по ссылке, слоты всего окна без параметров, создание записи); время UTC ISO 8601.
- [API-контракт: ошибки валидации и конфликты записи](issues/09-api-errors.md): решено в тикете об эндпоинтах — единый `{ message }`, 400 / 404 / 409 / 500.
- [Проверка приложения: уровни тестов и браузерный сценарий](issues/12-test-strategy.md): модульные (слоты, окно, поясы), интеграционные (каждая операция и ошибка, правила записи, тест гонки), прямые HTTP-запросы к серверу на случайном порту, тесты фронтенда с подменённым API, один браузерный сценарий Playwright на настоящих серверах в пакете `e2e/` (`mise run e2e`).
- [Исследование: серверные артефакты из OpenAPI для Spring Boot 4](issues/10-research-server-codegen.md): openapi-generator `spring` поддерживает Boot 4 и Jackson 3 с 7.20 (сейчас 7.27), ловит дрейф сигнатур компиляцией; Java-серверного эмиттера TypeSpec нет; альтернатива — ручной код + springdoc 3.x и oasdiff (шумные диффы).
- [Исследование: release-please для репозитория Java + Node](issues/13-research-release-please.md): manifest-режим, варианты — один корневой релиз с extra-files, linked-versions или независимые пакеты; GITHUB_TOKEN не запускает другие workflow (в том числе hexlet-check на тегах), нужен PAT/App, если это важно; появляется шаг release PR; action v5.0.0 (Node 24) или v4.
- [Design First: цепочка генерации и её команды](issues/11-design-first-chain.md): TypeSpec → OpenAPI → серверные интерфейсы и DTO (OpenAPI Generator 7.27 `spring`, Maven, в `target/`) + TS SDK (в git); `mise run generate`, проверка расхождения через `git diff` в `check`, `eol=lf` для сгенерированного (ADR-0003).
- [Качество и релизы: общая проверка, тест-нарушение, CI и release-please](issues/14-quality-and-releases.md): `check` = генерация → проверка сгенерированного (`git status --porcelain`, очистка SDK) → тесты → линтер → сборка; негативные тесты нарушения правил записи; CI — `check` + `e2e`; release-please v5, один корневой `simple`-релиз, `GITHUB_TOKEN`.
- [Реализация: вертикальные тикеты и первая сквозная функция](issues/15-vertical-slices.md): срез = одно поведение через контракт → генерацию → бэкенд → фронтенд → тесты; первый срез — удаление типа встречи с цепочкой генерации (реализован); далее расписание, окно записи, негативные и HTTP-тесты, Playwright, release-please; проверка сгенерированных файлов — только в CI.

## Out of scope

- Регистрация и авторизация, несколько владельцев (ADR-0001, ограничение проекта).
- Интеграции с внешними календарями, уведомления, платежи, командные встречи.
- Просмотр, отмена и перенос записи гостем, секретные ссылки и токены доступа к записи ([Роли и доступ](issues/01-roles-and-access.md)): гостю достаточно экрана подтверждения; можно рассмотреть отдельно.
- Профиль владельца (имя и т. п.) ([Роли и доступ](issues/01-roles-and-access.md)); показ имени владельца гостю — открытый вопрос.
- Отмена записи владельцем, снимок данных типа встречи в записи ([Модель записи](issues/06-booking-model.md)).
