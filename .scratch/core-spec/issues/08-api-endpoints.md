# API-контракт: эндпоинты, запросы и успешные ответы

Type: grilling
Status: resolved
Blocked by: 01, 02, 04, 05, 06

## Question

Какой набор эндпоинтов входит в контракт и как он делится на публичный API (гость) и API кабинета (владелец)? Как запрашиваются слоты (окно записи целиком или диапазон дат)? В каком формате передаётся время (UTC, со смещением, дата и время в поясе владельца)?

## Текущее состояние

Кабинет: `/api/event-types`, `/api/schedule`, `/api/bookings`; публичный: `/api/public/event-types/{slug}`, `…/slots?from=&to=`, `…/bookings`. Время — UTC в ISO 8601. Главная берёт список типов встреч из API кабинета (ADR-0001).

## Answer

Решено 2026-11-23 без отдельных вопросов: продуктовых развилок нет, всё выводится из ADR-0001, ADR-0002 и тикетов 01–07. Ошибки API решены здесь же (тикет «API-контракт: ошибки» закрыт со ссылкой сюда).

### Общие правила

- JSON; время в ответах — UTC в ISO 8601 с `Z`; во входных данных принимается момент ISO 8601 с `Z` или смещением, он нормализуется в UTC. Время расписания — местное `HH:mm` в поясе владельца (тикет «Расписание»).
- Кабинет — `/api/…` без авторизации (ADR-0001); публичный API — `/api/public/…`. Главная берёт список типов встреч из API кабинета (решение интервью по главной, ADR-0001), отдельного публичного списка нет.

### API кабинета (владелец)

| Операция | Метод и путь | Успешный ответ |
|---|---|---|
| Список типов встреч (в порядке создания) | `GET /api/event-types` | 200, массив типов |
| Тип встречи | `GET /api/event-types/{id}` | 200, тип |
| Создание | `POST /api/event-types` | 201, тип |
| Редактирование всех полей | `PUT /api/event-types/{id}` | 200, тип |
| Удаление (только без записей) | `DELETE /api/event-types/{id}` | 204, без тела |
| Расписание (сохранённое или по умолчанию) | `GET /api/schedule` | 200, расписание |
| Замена расписания целиком | `PUT /api/schedule` | 200, расписание |
| Все записи (прошедшие и будущие, по возрастанию начала) | `GET /api/bookings` | 200, массив записей |

Тип встречи: `id`, `slug`, `title`, `description?`, `durationMinutes`; в запросах `id` не передаётся. Расписание: `timeZone` (IANA), `intervals[]` из `dayOfWeek`, `startTime`, `endTime` (ответ отсортирован по дню и началу). Запись: `id`, `eventTypeId`, `eventTypeTitle` (текущее название), `guestName`, `guestEmail`, `startAt`, `endAt`, `status` (`CONFIRMED`), `createdAt`.

### Публичный API (гость)

| Операция | Метод и путь | Успешный ответ |
|---|---|---|
| Тип встречи по ссылке для записи | `GET /api/public/event-types/{slug}` | 200, тип |
| Свободные слоты всего окна записи | `GET /api/public/event-types/{slug}/slots` | 200, массив `{ startAt, endAt }` по возрастанию |
| Создание записи | `POST /api/public/event-types/{slug}/bookings` | 201, запись |

- Слоты запрашиваются без параметров: сервер сам вычисляет окно записи (14 дней в поясе владельца) и возвращает все свободные слоты в нём; пустой массив, если слотов нет. Параметры `from`/`to` и ограничение 62 дня убираются: окно небольшое, а диапазон за пределами окна по решению тикета «Окно записи» всё равно пуст.
- Тело записи: `startAt`, `guestName`, `guestEmail`. `startAt` должен в точности совпадать с началом свободного слота; конец вычисляет сервер.

### Ошибки

Формат один для всех ошибок: `{ "message": "…" }` с человекочитаемым текстом; машиночитаемых кодов и ошибок по полям нет — клиент различает случаи по HTTP-статусу и операции.

| Статус | Когда |
|---|---|
| 400 | Нарушены правила полей (тип встречи, расписание, данные гостя), некорректный JSON или параметр пути, неизвестный или не-IANA часовой пояс, пересекающиеся интервалы, конец интервала не позже начала |
| 404 | Нет типа встречи с таким `id` или ссылкой для записи (в том числе удалённого или со сменённой ссылкой) |
| 409 | Слот недоступен: занят, уже начался, вне окна записи, не совпадает с сеткой слотов (в том числе проигрыш одновременного запроса, ADR-0002); ссылка для записи уже занята; удаление типа встречи, по которому есть записи |
| 500 | Непредвиденная ошибка сервера, тот же формат |

Расхождения с текущей реализацией: нет `DELETE /api/event-types/{id}`; слоты сейчас запрашиваются с `from`/`to` (до 62 дней) и без окна записи; часовой пояс принимает фиксированные смещения; при создании записи не проверяется окно. Формат и коды ошибок совпадают.

Открытые вопросы: нет. Словарь не менялся.
