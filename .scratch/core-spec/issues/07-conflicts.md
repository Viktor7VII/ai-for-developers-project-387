# Конфликты: пересечения, примыкание, одновременные запросы

Type: grilling
Status: resolved
Blocked by: 05, 06

## Question

Блокирует ли запись одного типа встречи пересекающиеся слоты других типов? Считается ли примыкание интервалов (конец одной записи совпадает с началом другой) конфликтом? Какая гарантия нужна при одновременных запросах на один слот и какой ответ получает проигравший?

## Текущее состояние

Занятость общая для всех типов; примыкание разрешено; гонки — блокировка в приложении плюс уникальность начала в БД; проигравший получает 409.

## Answer

Решено 2026-11-23 без отдельных вопросов: развилок нет, всё выводится из ADR-0001 и тикетов 01–06.

1. **Общая занятость.** Запись любого типа встречи занимает время владельца целиком и исключает пересекающиеся слоты всех типов (ADR-0001: владелец один).
2. **Пересечение** — интервалы `[начало, конец)` полуоткрытые: записи и слоты конфликтуют, если `начало1 < конец2` и `начало2 < конец1`.
3. **Примыкание разрешено:** запись, заканчивающаяся в 10:00, не мешает слоту с 10:00. Буферов между встречами нет — это согласуется с шагом слотов, равным длительности (тикет «Модель слотов»).
4. **Записи вне текущего расписания** (после его изменения, тикет «Расписание») по-прежнему занимают время владельца: это реальные встречи.
5. **Гарантия отсутствия двойной записи** — ADR-0002: создание записи выполняется под блокировкой в приложении; внутри одной транзакции заново проверяются окно записи, сетка слотов, расписание, пересечения со всеми записями и существование типа встречи; блокировка отпускается после фиксации. Страховка — уникальность начала записи в базе. Из нескольких одновременных запросов на пересекающееся время успешен ровно один.
6. **Проигравший запрос** получает отказ «слот недоступен» — тот же, что для занятого, прошедшего, вне окна или вне сетки слота; код и формат ответа решает тикет «API-контракт: ошибки». Срабатывание страховки в базе даёт тот же отказ.
7. **Гонка удаления типа встречи и создания записи** разрешается той же транзакцией и связью записи с типом: побеждает одно из действий (тикет «Типы встреч»).
8. **Проверяемость:** правило должно быть закреплено тестом с одновременными запросами, который падает без блокировки; уровень и место теста решают тикеты «Проверка приложения» и «Качество и релизы».

Расхождения с текущей реализацией: при записи не проверяется окно записи (тикет «Окно записи»); остальное совпадает (общая занятость, примыкание, блокировка + уникальность начала, тест на гонку есть).

Открытые вопросы: нет. Словарь не менялся. Добавлен ADR-0002.
