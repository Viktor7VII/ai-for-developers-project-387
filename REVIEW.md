# Критерии ревью

Чек-лист для людей и для авторевью (`.github/workflows/opencode-review.yml`). Правила проекта — в `AGENTS.md`, термины — в `GLOSSARY.md`, решения — в `docs/adr/`. Замечание должно указывать файл и строку, причину и исправление; серьёзность: **блокирует**, **важно**, **мелочь**.

## Объём и требования

- Изменение соответствует связанному Issue и спецификации; критерии приёмки выполнены, лишней функциональности нет.
- Поведение для гостя и владельца описано терминами `GLOSSARY.md`; новый термин добавлен в словарь в том же PR.

## Контракт и генерация (ADR-0003)

- API меняется сначала в `contracts/main.tsp`; `contracts/openapi/` и SDK в `frontend/src/shared/api/generated/` перегенерированы `mise run generate` и закоммичены; вручную сгенерированный код не правится.
- Контроллеры реализуют сгенерированные интерфейсы, логика — в собственном коде.
- Ошибки — в формате `ErrorResponse` с кодами из контракта (`400` / `404` / `409`).

## Правила записи

- Свободные слоты учитывают расписание и часовой пояс владельца (IANA), окно записи 14 дней и сетку слотов.
- Доступность перепроверяется при создании записи; любая запись занимает время владельца для всех типов встреч; защита от двойной записи (ADR-0002) не ослаблена.
- Проверки входных данных выполняются до проверки слота и не занимают время при отказе.
- Данные записи после создания неизменны, кроме заметки владельца.

## Данные гостя и владельца

- Гость не получает данных, предназначенных владельцу: публичный API (`/api/public/...`) и гостевые страницы не раскрывают заметку владельца.
- Тема разговора гостя неизменна после создания записи и не смешивается с заметкой.
- Секретов, ключей и токенов в коде, конфигурации и логах нет.

## Хранение

- Схема H2 обновляется `ddl-auto=update`: новые колонки допускают пустое значение; существующие записи работают без миграции; миграционные скрипты не добавляются без отдельного решения.

## Frontend

- Тексты интерфейса — на русском, в терминах словаря; состояния загрузки, пустого списка и ошибки есть.
- Таблицы и формы пригодны на узком экране; длинный текст не ломает вёрстку.
- Повторяющиеся элементы управления имеют уникальные доступные названия; формы сохраняют введённые данные при ошибке сервера.

## Тесты и проверки

- Новое поведение покрыто тестами через существующие швы: backend — Spring Boot + MockMvc, frontend — маршрут приложения с подменённым API-клиентом; тесты проверяют поведение, а не устройство.
- Негативные и граничные случаи покрыты (ошибки, пустые значения, лимиты).
- `mise run check` зелёный; браузерный сценарий `mise run e2e` проходит.

## Git и PR

- Коммиты — Conventional Commits со строками `Refs:` с полными URL Issues; без `#номеров` и ключевых слов закрытия в сообщениях коммитов.
- Описание PR заполнено по шаблону: проверки, риск, откат.
- `.github/workflows/hexlet-check.yml` не изменён; workflow используют минимальные права и закреплённые версии actions.
