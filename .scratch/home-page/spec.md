# Главная страница для гостя

Status: resolved

Итог интервью (`/grill-with-docs`). Термины — по `GLOSSARY.md`.

## Решения

1. Главная страница `/` предназначена для гостя. Кабинет владельца остаётся на `/admin`; `/` больше не перенаправляет в кабинет.
2. Человек, который записывается, называется «гость» (не «посетитель»). Подтверждённая встреча называется «запись».
3. Один владелец без входа в систему (ADR-0001).
4. Типы встреч перечислены прямо на главной: каждая карточка показывает название, длительность, описание (обрезанное до 3 строк) и кнопку «Записаться», ведущую на ссылку для записи `/book/:slug`. Отдельной общей кнопки нет, slug в карточке не показывается.
5. В шапке главной — небольшая ссылка «Кабинет владельца» на `/admin`.
6. Минимальный лендинг: заголовок «Календарь звонков» и одна-две строки о записи на звонок без регистрации. Без блока «как это работает», отзывов и картинок.
7. Список типов встреч берётся из существующего `GET /api/event-types`; контракт не меняется (зафиксировано в ADR-0001).
8. Показываются все типы встреч в порядке создания, без проверки наличия слотов.
9. Пустое состояние: «Владелец пока не открыл запись.» Если сервер недоступен — сообщение об ошибке, как на остальных страницах.
10. Страница записи `/book/:slug` уже реализована, заглушка не нужна.

### Второе интервью

11. Уже готовая реализация главной в ветке `feat/home-page` сохраняется и доводится до решений этого документа; с нуля не переписывается.
12. Работающая страница записи `/book/:slug` и бронирование в рамках этой фичи не меняются.
13. Термины — по `GLOSSARY.md`: «гость», «запись», «ссылка для записи» (не «посетитель», «бронирование», «публичная ссылка»).
14. Внешний вид: тема и цвета как у остальных страниц (Mantine, основной цвет indigo); контент по центру шириной не больше ~960 px; карточки в сетке — одна колонка на телефоне, две начиная с планшета; в шапке слева название сервиса, справа ссылка «Кабинет владельца»; без тёмной темы и переключателя.
15. Тексты:
    - заголовок: «Календарь звонков»;
    - подзаголовок: «Выберите тип встречи и запишитесь на удобное время — регистрация не нужна.»;
    - кнопка в карточке: «Записаться»;
    - ссылка: «Кабинет владельца»;
    - пустое состояние: «Владелец пока не открыл запись.»;
    - ошибка: заголовок «Не удалось загрузить типы встреч» и текст ошибки сервера.
16. Пока список загружается, показывается индикатор загрузки, как на страницах кабинета.

## Критерии готовности

1. `/` открывает главную для гостя, кабинет доступен по `/admin`.
2. Карточки показывают название, длительность и описание (до 3 строк); «Записаться» ведёт на `/book/:slug`.
3. Есть ссылка на кабинет, состояния загрузки, пустого списка и ошибки.
4. Вёрстка соответствует решению 14 на ширине телефона и десктопа (проверяется вручную в браузере).
5. Тесты на уровне маршрута `/` с подменённым API покрывают пункты 1–3.
6. `mise run check` зелёный локально, `project-check` и `hexlet-check` зелёные в GitHub Actions.

## Тесты

Шов: всё приложение, открытое на `/`, с подменённым API-клиентом. Проверяются карточки и ссылки на `/book/:slug`, переход на страницу записи, ссылка на кабинет, состояния загрузки, пустого списка и ошибки.

## Открытые вопросы (следующие этапы, не решены)

- Публичный эндпоинт списка типов встреч: понадобится, когда появится авторизация владельца (см. ADR-0001). Когда и в каком виде — не решено.
- Нужна ли на главной информация о владельце (имя, фото, описание) — не обсуждалось.
- Нужна ли возможность скрыть отдельный тип встречи с главной — не обсуждалось.
