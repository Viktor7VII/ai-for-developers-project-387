# Расписание: рабочие дни, часы и часовой пояс владельца

Type: grilling
Status: resolved
Blocked by: 01

## Question

Как задаются рабочие дни и часы: один интервал в день или несколько, одинаковые для всех дней или по дням? Где задаётся часовой пояс владельца (в расписании или в профиле) и какое значение по умолчанию? Влияет ли изменение расписания на уже созданные записи?

## Текущее состояние

Недельные интервалы, несколько в день, без пересечений; часовой пояс хранится в расписании, по умолчанию UTC; без сохранённого расписания — пн–пт 09:00–17:00; записи хранят точное время и при изменении расписания не меняются.

## Answer

Решено в интервью (grilling), 2026-11-23.

1. **Структура рабочего времени — вариант (a), без упрощений.** Для каждого дня недели допускается любое количество интервалов; перерывы задаются разделением рабочего времени на несколько интервалов; у разных дней могут быть разные часы. Расхождений с текущей реализацией нет.
2. **Правила интервалов — вариант (a), без изменений.** Время с точностью до минуты (`HH:mm`, 00:00–23:59); начало строго раньше конца; интервал не переходит через полночь, `24:00` не поддерживается; интервалы одного дня не пересекаются, примыкание разрешено; пустое расписание допустимо и означает, что владелец недоступен. Расхождений с текущей реализацией нет.
3. **Часовой пояс владельца — вариант (a).** Пояс — часть расписания, владелец меняет его в кабинете; по умолчанию `UTC`; выбор из списка поясов IANA и кнопка «Использовать мой часовой пояс» сохраняются; отдельной настройки в конфигурации нет. Расхождений с текущей реализацией нет (см. уточнение 3а).
3а. **Только часовые поясы IANA — вариант (a).** И API, и интерфейс принимают только идентификаторы поясов IANA (например, `Europe/Moscow`, `UTC`); фиксированные смещения вроде `+03:00` и `UTC+3` отклоняются как ошибка валидации. Пояс по умолчанию `UTC` остаётся допустимым.
   - Расхождение с текущей реализацией: бэкенд сейчас принимает любое значение, которое разбирает `ZoneId.of`, включая фиксированные смещения; интерфейс уже предлагает только IANA.
4. **Записи вне нового расписания — вариант (a).** Базовое правило уже закреплено в README («изменение расписания не должно менять уже созданные записи»). Изменение расписания проходит без предупреждений и запретов, даже если будущие записи оказываются вне нового расписания; такие записи сохраняют время и остаются в силе, новые слоты считаются по обновлённому расписанию, владелец видит записи в своём списке. Предупреждения, отмена и блокировка изменения не добавляются. Расхождений с текущей реализацией нет.
   - Занимают ли такие записи время владельца при расчёте слотов — решает тикет «Конфликты».
5. **Смена часового пояса — вариант (a).** Местные часы расписания сохраняются без пересчёта: «09:00–17:00 `Europe/Moscow`» после смены пояса становится «09:00–17:00 `Asia/Yekaterinburg`». Абсолютное время существующих записей не меняется; новые слоты считаются в новом поясе. Расхождений с текущей реализацией нет.
6. **Летнее и зимнее время — вариант (a), текущее поведение.** Часы расписания — настенное время в поясе владельца; в день перехода абсолютное время интервалов сдвигается вместе с часами. Несуществующее местное время (весенний переход) сдвигается вперёд на величину перехода; у повторяющегося (осенний переход) берётся первое наступление. Особых правил нет. Расхождений с текущей реализацией нет.
7. **Расписание по умолчанию — вариант (a), текущее.** Пока владелец не сохранил расписание, действует «понедельник–пятница, 09:00–17:00, `UTC`»; оно не хранится в базе и при первом сохранении заменяется расписанием владельца. Пустого расписания по умолчанию нет. Расхождений с текущей реализацией нет.

Расхождения с текущей реализацией: одно — бэкенд принимает фиксированные смещения часового пояса (решение 3а требует только IANA).

Передано другим тикетам: занимают ли записи вне расписания время владельца — «Конфликты».

Открытые вопросы: нет. Словарь не менялся: определение «Расписание» (недельные интервалы доступности владельца в его часовом поясе) решениям соответствует, новых терминов нет.
