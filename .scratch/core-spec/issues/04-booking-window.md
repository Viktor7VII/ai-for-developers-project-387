# Окно записи: 14 календарных дней

Type: grilling
Status: resolved
Blocked by: 03

## Question

Окно записи — 14 календарных дней: начинается сегодня или завтра? В чьём часовом поясе считаются границы дней (владельца или гостя)? Входит ли 14-й день? Есть ли минимальный отступ от текущего момента для слотов сегодняшнего дня?

## Текущее состояние

Окна нет: доступен любой будущий слот, один запрос слотов — до 62 дней; прошедшие слоты исключаются, минимального отступа нет.

## Answer

Решено в интервью (grilling), 2026-11-23.

1. **Начало окна — вариант (a).** 14 календарных дней отсчитываются от сегодняшнего дня включительно: сегодня и следующие 13 дней. Сегодняшние слоты доступны, если ещё не начались; слоты, начинающиеся ровно сейчас или раньше, исключаются.
   - Расхождение с текущей реализацией: окна нет, доступен любой будущий слот.
2. **Минимальный отступ — вариант (a), нет.** Доступен любой слот, который ещё не начался, даже если до него осталось несколько минут. Расхождений с текущей реализацией нет.
3. **Часовой пояс окна — вариант (a), пояс владельца.** Окно одинаково для всех гостей: сегодняшний день владельца и следующие 13 календарных дней в его поясе. Время слотов гость видит в своём поясе. Серверу пояс гостя не нужен. Расхождение с текущей реализацией: окна нет (см. решение 1).
4. **Границы окна — вариант (a).** Окно — с 00:00 сегодняшнего дня до 00:00 пятнадцатого дня по времени владельца: 14-й день входит целиком. Слот попадает в окно, если в окне его начало (интервалы не переходят через полночь, поэтому слот целиком лежит в одном дне окна). При создании записи сервер повторно проверяет это условие; запись вне окна отклоняется как недоступный слот. Окно сдвигается в полночь по времени владельца. Расхождение с текущей реализацией: окна нет (см. решение 1).
5. **Открытая страница при наступлении нового дня — вариант (a).** Автообновления в полночь или по таймеру нет. Актуальность обеспечивает повторная проверка окна и доступности слота сервером при создании записи; если слот стал недоступен, запись отклоняется, а страница обновляет список свободных слотов (как при занятом слоте сейчас). Новый 14-й день гость увидит после перезагрузки. Расхождений с текущей реализацией нет.
6. **Окно при изменении расписания и пояса — вариант (a).** (1) Окно считается по текущему поясу владельца в момент запроса; после смены пояса границы сразу пересчитываются. (2) Расписание влияет только на слоты внутри окна; при пустом расписании окно есть, слотов нет. (3) Окно ограничивает только создание новых записей; существующие записи вне окна (в том числе созданные до появления окна) остаются в силе. (4) Запрос слотов за пределами окна возвращает пустой список, а не ошибку; форму и ограничения запроса решает тикет «API-контракт: эндпоинты».
7. **Размер окна — вариант (a).** Окно — фиксированные 14 календарных дней, а не настройка владельца. Дни перехода на летнее или зимнее время (23 или 25 часов) остаются одним календарным днём окна.

Расхождения с текущей реализацией: окна записи нет — доступен любой будущий слот, один запрос слотов охватывает до 62 дней (решения 1, 3, 4, 7); остальные решения совпадают с текущим поведением.

Передано другим тикетам: форма и ограничения запроса слотов — «API-контракт: эндпоинты»; формирование и шаг слотов — «Модель слотов».

Открытые вопросы: нет. Словарь: добавлен термин «Окно записи».
