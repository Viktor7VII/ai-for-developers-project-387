# Роли и доступ: кто владелец и что доступно гостю

Type: grilling
Status: resolved
Blocked by: —

## Question

Как задан заранее определённый владелец: нужен ли профиль владельца (имя, email, часовой пояс и т. п.) и откуда берутся его данные (конфигурация, база)? Какие страницы и действия доступны только владельцу, а какие гостю, при отсутствии регистрации и авторизации?

## Текущее состояние

Сущности владельца нет; кабинет `/admin` и API кабинета открыты (ADR-0001); гость видит главную и `/book/:slug`.

## Answer

Решено в интервью (grilling), 2026-11-23.

1. **Модель владельца — вариант (a).** Отдельного профиля владельца нет: владелец единственный и неявный, как в текущей реализации. Не добавляются сущность владельца, его имя и операции API для профиля. Часовой пояс владельца решается в тикете «Расписание».
2. **Возможности гостя — вариант (a).** Без регистрации гостю доступны ровно четыре действия: увидеть на главной список типов встреч; открыть страницу типа встречи по ссылке для записи; посмотреть свободные слоты; создать запись, указав имя и email. После записи гость видит экран подтверждения и не может повторно открыть свою запись.
3. **Доступ к кабинету** — уже решён ADR-0001: кабинет `/admin` и его операции открыты без входа.

Следствия (не отдельные решения):

- Публичные операции — только четыре действия гостя; всё остальное (управление типами встреч, расписание, список записей) — операции кабинета. Раскладку по эндпоинтам решает тикет «API-контракт: эндпоинты».
- Гость не видит чужие записи и данные других гостей: ему доступны только свободные слоты.

Вне рамок спецификации: секретные ссылки и токены доступа к записи, просмотр записи гостем, отмена и перенос записи.

Расхождений с текущей реализацией нет.

Открытые вопросы:

- Показывать ли гостю имя владельца — открыт; если понадобится, рассмотреть профиль владельца в конфигурации (вариант b).

Словарь не менялся: новых терминов нет, определения «Владелец» и «Гость» решениям соответствуют.
